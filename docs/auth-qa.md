# Проверка регистрации и ЛК — 27 октября 2026

Результат: локальная реализация проверена. Публикация не выполнялась.

## Реализовано

Самостоятельная регистрация по имени, логину и паролю; автоматический вход после регистрации; повторный вход; восстановление сеанса после обновления страницы и перезапуска сервера; профиль; выход с отзывом сеанса. Расписание и автобусы остаются публичными. Личный журнал требует входа и сейчас показывает отсутствие подключения к источнику оценок. Демонстрационные оценки вынесены в `#/demo`.

## Автоматическая проверка

`npm test`: 35/35 тестов. Проверены регистрация, дубликаты и конкурентная регистрация, вход/выход, сохранение базы между запусками, истечение и подделка сеанса, изоляция двух аккаунтов, параметры cookie, отсутствие исходного пароля и токена в базе, CSRF, лимиты запросов, битый и большой JSON, приватные файлы, отсутствие кэширования API, гонки клиентских ответов и экранирование имени в профиле. Существующие тесты расписания и транспорта проходят.

Проверки синтаксиса новых модулей и `git diff --check` проходят. Приватная база `server/.data/accounts.sqlite` исключена из Git. Node.js 24.14 сообщает, что его SQLite API пока экспериментальный; реализация проверена именно на этой версии, рабочая версия Node закреплена в package.json.

## Независимый обзор

Найдено и исправлено два замечания. Для каждого тест сначала воспроизвёл ошибку, затем прошёл:

1. Запоздалый 401 старого запроса оценок мог отменить новый вход. Ответ теперь проверяет ревизию сеанса перед сбросом пользователя.
2. Старый service worker мог кэшировать успешные приватные GET до установки нового worker. Клиент и сервер используют POST для всех приватных чтений; GET-варианты API отклоняются с 405. Новый worker дополнительно исключает `/api/` из перехвата.

Дополнительных существенных замечаний в серверном разграничении доступа и раздаче файлов обзор не выявил. Это ограниченный обзор изменений, не заявление о полном аудите безопасности.

## Браузер

Проверено через настоящий интерфейс с отдельным синтетическим аккаунтом:

- Несовпадающие пароли: форма показывает ошибку и не отправляет регистрацию.
- Успешная регистрация: создан аккаунт, открыт профиль.
- Обновление страницы: вход сохранён.
- «Мои оценки»: нет подстановки демонстрационных оценок в личный профиль.
- Выход: показана форма входа, прежний сеанс отозван.
- Неверный пароль: общее сообщение об ошибке; правильный пароль затем открывает профиль.
- Переключение видимости пароля работает; поля поддерживают менеджеры паролей.
- Занятый логин: показано сообщение, фокус возвращается в поле логина.
- Вкладка успеваемости после выхода предлагает вход и регистрацию; пример журнала и его предметы доступны по отдельному маршруту.
- Ширины 390 и 320 px: горизонтального переполнения нет, у полей шрифт 16 px, длинная форма прокручивается над нижней навигацией.

Визуально просмотрены формы и профиль: сохранены светлый фон, зелёный акцент, типографика и общая навигация выбранного дизайна. Пароль имеет отдельную подпись; кнопка показа пароля не попадает в accessible name поля. Исправлены отступ перед паролем и ширина кнопки «Мои оценки».

Снимки находятся в `design/qa/auth/`: `register-mobile.png`, `register-320.png`, `login-mobile.png`, `login-error.png`, `profile-mobile.png`, `personal-grades-empty.png`, `signed-out-grades.png`. Они содержат только синтетические данные; пароль на снимках скрыт.
