# Личный кабинет

Нужен **Node.js 24.14+ версии 24.x**. Установите зависимости из корня: `npm ci`.

Из корня проекта:

```sh
npm start
```

Открыть `http://127.0.0.1:4173/#/register`. Студент сам задаёт имя, уникальный логин и пароль. После регистрации вход выполняется автоматически. Логин нечувствителен к регистру, пароль — чувствителен. Пароли: 12–128 символов, без обязательной смеси специальных символов.

`npm test` запускает серверные интеграционные тесты и тесты веб-клиента.

## Данные

По умолчанию база находится в `server/.data/accounts.sqlite`, вне публичной папки `web/`. Каталог исключён из Git. После перезапуска аккаунты и действующие сеансы сохраняются. Для резервного копирования остановите сервер и сохраните базу в закрытом месте.

Пароль хранится как scrypt-хеш с отдельной случайной солью. Токен сеанса содержит 32 случайных байта; в базе хранится только его SHA-256-хеш. Сеанс действует 7 дней, выход отзывает текущий сеанс. Пароли и токены не сохраняются в localStorage и не выдаются в JSON.

Регистрация создаёт аккаунт этого приложения. Она пока не подтверждает личность студента и не даёт доступа к чужим или реальным оценкам. Сервер получает пользователя из сеанса; переданный клиентом userId не определяет доступ. Источник оценок и процедура привязки к студенту колледжа ещё не подключены. Восстановления пароля пока нет.

## API

Все запросы — **POST**, `Content-Type: application/json`, с точным `Origin`, совпадающим с `PUBLIC_ORIGIN`. Приватные чтения также используют POST: прежняя версия service worker кэшировала все успешные GET, поэтому переход на POST защищает первую загрузку обновлённого клиента, пока новый worker ещё устанавливается. GET-варианты API возвращают 405. Ответы API имеют `Cache-Control: no-store`.

- `/api/auth/register`: `{displayName, username, password}` → `{user}`, cookie сеанса.
- `/api/auth/login`: `{username, password}` → `{user}`, новый cookie сеанса.
- `/api/auth/session`: `{}` → `{user}` или `{user: null}`.
- `/api/auth/logout`: `{}` → 204, отзыв и удаление cookie.
- `/api/account`: `{}` → профиль текущего пользователя; без сеанса — 401.
- `/api/grades`: `{}` → `{connected: false, subjects: []}`; без сеанса — 401.

Есть ограничение размера JSON 16 KiB, числа параллельных проверок пароля, попыток входа (20/15 мин на IP) и регистрации (50/час на IP). Лимиты находятся в базе и сохраняются между запусками. Самостоятельный Node-сервер использует адрес сокета; только отдельный Vercel-обработчик принимает IP из заголовков, которые выставляет платформа.

## Размещение

Приложение опубликовано на https://tkpst-schedule.vercel.app/ с базой Neon. Текущая инструкция облачной версии — [`docs/vercel-neon.md`](../docs/vercel-neon.md). Ниже описан самостоятельный Node/SQLite-режим.

GitHub Pages раздаёт статические файлы и не запускает этот сервер. Для ЛК нужен отдельный хостинг Node.js с постоянным диском; эта задача его не публикует.

Предполагается один процесс сервера и локальная SQLite-база. Несколько независимых контейнеров с временными базами будут иметь разные аккаунты. Для масштабирования нужен общий источник данных и общие лимиты попыток.

Переменные окружения:

- `PORT`: 4173 по умолчанию.
- `HOST`: 127.0.0.1 по умолчанию — доступ только с этого компьютера.
- `PUBLIC_ORIGIN`: точный внешний адрес, по умолчанию `http://127.0.0.1:4173`.
- `AUTH_DB_PATH`: закрытый абсолютный путь к постоянной SQLite-базе.

При размещении за HTTPS-прокси укажите `PUBLIC_ORIGIN=https://ваш-домен` и нужный `HOST`. Сервер включает cookie `__Host-…; Secure; HttpOnly; SameSite=Lax`. Сам Node-сервер обслуживает HTTP за TLS-прокси. Для публичного прослушивания без HTTPS-конфигурации запуск запрещён. Все клиенты и API должны иметь один origin.

`.env` автоматически не читается обычным `npm start`. При использовании файла: `node --env-file=.env server/index.mjs`; пример — `.env.example` в корне.

Основа реализации: [Node.js crypto](https://nodejs.org/docs/latest-v24.x/api/crypto.html), [Node.js SQLite](https://nodejs.org/docs/latest-v24.x/api/sqlite.html), [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).
